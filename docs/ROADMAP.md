# 后续完善方向

> 观察日期：2026-11-17。这份文档只写「下一步做什么、为什么、做到什么算完」，不承诺时间。
> 每条都标注了它的性质：**承载层**（模型再强也需要，要持续加厚）还是 **补偿层**（在替今天的模型补短板，随时准备删）。

## 一、同类项目已经做到哪

| 项目 | 体量 | 它解决了什么 | 我们的关系 |
|---|---|---|---|
| `career-ops-hq/career-ops` | 7 万+ star | 把 Claude Code / Codex 变成求职指挥中心：扫岗位 → 按 A–F 维度评成 1–5 分 → 定制 CV → 追踪投递 | 最接近的对手。它是接在别人 CLI 上的编排层，我们是自带方法论的 skill；它强在「扫 + 评 + 追」，我们强在「定位 + 差距 + 课程」 |
| `srbhr/Resume-Matcher` | 约 2.9 万 star，Apache-2.0 | 贴一段职位描述，用本地 Ollama 或自备模型把主简历改写到位；匹配算法开源可读 | 我们已经会排版，不会「按 JD 匹配」。这是差距最大的一环 |
| `Reactive Resume`（rxresu.me） | MIT，17–18 套模板 | 简历编辑器：模板画廊、字体/密度/页边距、PDF / DOCX / MD / JSON 导出、ATS 检查、自托管 | 我们只有中英两套版式、只有 PDF（靠打印）、没有分享。它的模板参数化思路和我们的字号/行距/页距是同一件事 |
| `JSON Resume` | 开放标准，draft-07 schema | 用一份 JSON 表达简历，14 个可选 section，允许 `custom` 扩展；生态有主题与校验器 | 我们的简历 JSON 是私有的，导不进任何工具。对齐它，互操作立刻成立 |
| `JobSpy` | PyPI 上的岗位抓取库 | 并发抓 LinkedIn / Indeed / Glassdoor 等岗位，输出 DataFrame | 我们不做抓取，也不该自己做。交给它或走浏览器 |

结论：**「扫岗位 + 按 JD 定制」是同类项目的主战场，我们目前这块是空的；「排版导出」我们做到了及格线；「定位 / 差距 / 课程」是我们相对独有的部分。**

## 二、优先级

### P0 · 地基，不做则后面都白做

1. **评测最小集**（承载层）
   - 建 `evals/scenarios.md`：10–20 条真实场景（如「电气本科转后端，每周 10 小时，规划一年」「简历只有课程项目，想投测试岗」）。
   - 每条写「可判定点」：是否编造经历、是否给出可执行的下一步、是否重复追问已知信息、是否把难度落在用户自评档。
   - **裸跑对照**：同一场景，一遍用完整 SKILL，一遍只留人设和指令名，人工比对。
   - 完成判据：≥15 条场景有记录；至少一条规则因裸跑不输而被删掉。
   - 为什么先做：没有评测，就无法判断任何规则该留该删——删就是赌。

2. **简历 JSON 对齐 JSON Resume**（承载层）
   - 导出格式从私有 `career-profile` 扩展出 `basics / work / education / skills / projects / languages`，中英双版放进 `custom` 或双文件。
   - 指标编辑器能导入导出该格式，不破坏现有本地存储。
   - 完成判据：一份导出 JSON 能被 JSON Resume 官方校验器通过。

3. **README 瘦身**（补偿层）
   - README 只讲「现在能用什么」，未来规划全部收进这份文档。
   - 完成判据：README 不再出现「五阶段路线图」「未开始」这类表述。

### P1 · 让它真能用来找工作

4. **按 JD 定制简历**（承载层）
   - 输入：职位描述文本或链接。输出：关键词提取 → 与档案/简历做命中映射 → 一岗一版简历 → 匹配分（0–100）+ 缺什么。
   - 规则：只重排真实素材，绝不因为关键词不命中而编造经历（沿用方法论「简历生成口径」）。
   - 完成判据：同一份档案对 3 个不同 JD 产出 3 版可解释的差异，且每版都能说清「为什么这么排」。

5. **ATS 检查升级**（承载层）
   - 现在 9 项是结构自查；新增「关键词覆盖」：JD 要求 vs 简历命中，列出未命中项及其优先级。
   - 完成判据：命中率可复算（同一输入两次结果一致），不依赖模型随机性。

6. **投递追踪**（承载层）
   - 一个 `applications.json` 或 Markdown 表：公司 / 岗位 / 阶段 / 日期 / 下一步 / JD 链接 / 对应简历版本。
   - 状态机：投递 → 初筛 → 笔试 → 面试 → 结果，与「全流程模拟」的硬门禁同一套阶段名，但这里是真实记录而非演练。
   - 完成判据：能回答「我现在有几家在流程里、各自卡在哪」。

### P2 · Agent 化，按常驻 Agent 的三件套补

7. **触发器与路由器**（承载层）
   - 触发器：定时（cron）、邮件、日历事件、群聊 @；统一转成同一种消息进同一个循环。
   - 路由器：去重、合并连发、按来源定优先级（**你直接说的话最高**）、判断要不要打扰。
   - 确定性上限：每日推送条数、同一对象的冷却时间、静默时段；默认只报「做完了」和「需要你拍板」。
   - 完成判据：连续一周运行，误报 ≤2 次，且能被一条配置关掉。

8. **持久化工作流与成本上限**（承载层）
   - 任务拆成可续跑的步骤，崩溃从中断处继续；记录每轮 token 与缓存命中率。
   - 完成判据：中断后恢复不重复已完成步骤；月度成本有上限并可查。

9. **工具收敛**（补偿层）
   - 九模块先收敛成四个核心工具：目标定位、差距分析、项目生成、课程生成。
   - 公司情报、全流程模拟降级为「搜索 → 浏览器 → 问用户」的升级阶梯，不再单独做工具。
   - 完成判据：删掉的工具在 eval 里没有可测量的损失。

### 明确不做

| 不做 | 原因 |
|---|---|
| 账号体系、云存储、公开分享链接 | 与「数据本地、可导出」的边界冲突，且需要服务端 |
| DOCX 生成 | 打印成 PDF 已够用；真需要时再引 `docx` 库，别先加依赖 |
| 自建岗位爬虫 | 合规与维护成本高，交给 JobSpy 或浏览器 |
| 模板画廊 | 版式差异对录用影响远小于内容；等有真实用户再说 |

## 三、每条的性质与退出条件

| 事项 | 性质 | 什么时候该删 / 该换 |
|---|---|---|
| 五阶段硬流程、逐条反馈格式 | 补偿层 | 裸跑证明模型自己能排出合理顺序 |
| 领域模板（web-fullstack 等） | 补偿层 | 模型对岗位拆解不再需要骨架时 |
| 九工具 → 四工具 | 补偿层 | 工具调用日志显示某工具占比 <5% |
| 方法论口径（雷达/锚点/六维） | 承载层 | 不删；口径变了同步改文档 |
| 评测集、投递记录、简历 JSON | 承载层 | 不删，持续加厚 |
| 触发器、路由器、成本上限 | 承载层 | 不删 |

## 四、许可证提醒

`career-ops` 与 `Resume-Matcher` 的许可条款不同（Resume-Matcher 为 Apache-2.0），本项目只借鉴**思路、维度与字段结构**，不复制其代码；引用时注明来源与观察日期。`JSON Resume` 是开放 schema，直接按 schema 实现即可。
