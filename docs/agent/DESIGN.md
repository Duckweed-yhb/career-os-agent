## 一、功能：有哪些能力

> **一句话**：CareerOS Agent 是本仓库 skill 层的 Agent 化升级——保留九大职业能力，新增**主动编排、跨会话记忆、可视化看板**三层，让它从「你问它答」变成「自主运转的职业成长陪练」。
> **状态约定**：⚪ 待确认 / 🟢 已明确 / 🔵 进行中

### 1.1 能力总览

```
CareerOS Agent（三层结构）
├── Agent 运行时层（内核，必备）
│   ├── 意图理解        听懂目标/背景/情绪，拆成任务
│   ├── 规划与编排      多步工作流（定位→差距→项目→课程）
│   ├── 工具调用        九大职业模块 = tools
│   ├── 反思与调整      结果回写、难度校准、路径重排
│   └── 主动跟进        跨会话续接、提醒、复盘（可选开关）
│
├── 工具层（九大能力 = 可插拔工具）
│   ├── 目标定位雷达     ├── 技能差距分析
│   ├── 项目生成器       ├── 课程生成器
│   ├── 作品集构建       ├── 简历生成评估
│   ├── 模拟笔试面试     ├── 公司情报
│   └── 招聘全流程模拟
│
└── 记忆与数据层
    ├── 短期对话记忆     当前会话上下文
    ├── 长期职业档案     career-profile（画像、目标、项目、难度偏好）
    ├── 向量索引 RAG     简历/课程/复盘可检索
    └── 学习进度         课程验收勾选、里程碑

横切：📊 可视化看板（雷达/进度/路线） · 🔒 数据自持 · 📦 可导出
```

### 1.2 内核（Agent 运行时）能力

| 能力 | 说明 | 状态 |
|------|------|:---:|
| 意图理解 | 从自然语言解析目标岗位、经验水平、时间预算、情绪信号 | ⚪ |
| 规划与编排 | 按"定位→差距→项目→课程"多阶段工作流自动推进 | ⚪ |
| 工具调用 | 把九大模块封装为 tools，按需调用并解析结果 | ⚪ |
| 反思与调整 | 每阶段回写档案、按用户反馈平移难度、重排路径 | ⚪ |
| 主动跟进 | 跨会话续接上次进度、到点提醒、阶段复盘（用户可选开启） | ⚪ |
| 统一契约 | 工具输入/输出统一 schema，可审计、可回滚 | ⚪ |

### 1.3 工具层（九大职业能力）

> 全部继承自 skill 层，从"提示词里的流程"升级为"结构化的工具接口"。

#### 1.3.1 目标定位与能力雷达

- 解析兴趣与背景，锁定 1–3 个目标岗位，生成六维能力雷达（语言框架 / 数据存储 / 工程实践 / 架构设计 / 领域知识 / 软技能）。

#### 1.3.2 技能差距分析

- 对比当前水平与目标岗位要求，按"影响 × 紧迫度"排序缺口，优先打 20% 关键缺口。

#### 1.3.3 项目生成器

- 按缺口生成工业级复杂度项目构思，含技术栈、难点预测、验收标准；拒绝玩具项目。

#### 1.3.4 课程生成器

- 把选定项目拆成边做边学的 Markdown 课程，每课含知识增量 + 项目增量 + 可勾选验收标准。

#### 1.3.5 作品集构建

- 把项目转成简历亮点，输出简历描述优化 + GitHub README 指南。

#### 1.3.6 简历生成与评估

- 生成：从档案、项目、课程验收起草一版，一岗一版，输出结构化 JSON 供本地编辑器（`tools/resume-builder/index.html`）排版导出。
- 评估：六维打分（可扫读性 / 成果优先 / 岗位匹配 / 项目表述 / 差异化 / 打磨），按必修/建议/可选列问题。

#### 1.3.7 模拟笔试与面试

- 笔试：限时出题、逐题打分；面试：一次一题、每答反馈、结束回写强项缺口。

#### 1.3.8 公司情报

- 查证面试流程、笔试风格、薪资；带来源与时效；查不到一律留空不编造。

#### 1.3.9 招聘全流程模拟

- 投简历 → 初筛 → 笔试 → 面试 → 结果，硬门禁阶段判定，区分"模拟判定"与"真实建议"。

### 1.4 Agent 新增能力（skill 没有的）

| 能力 | 说明 | 状态 |
|------|------|:---:|
| 主动跟进 | 不用每次重敲命令，自动续接上次进度；到里程碑主动复盘 | ⚪ |
| 跨会话记忆 | 档案 + 向量索引，下个会话能"记得"你的目标与进度 | ⚪ |
| 任务编排 | 一条指令驱动完整流水线，而不是逐条调用 | ⚪ |
| 可视化看板 | 能力雷达、学习进度、路线图可视化呈现 | ⚪ |
| 数据自持与导出 | 全部档案本地自持，可导出 Markdown / JSON | ⚪ |

### 1.5 能力分级（建议开发顺序）

| 级别 | 含义 | 归入的能力 |
|------|------|-----------|
| **P0 · 地基** | 先有运行时与记忆 | 意图理解、工具调用、统一契约、档案持久化 |
| **P1 · 核心工具** | 从 skill 平移即可用 | 目标定位、差距分析、项目生成、课程生成 |
| **P2 · 求职闭环** | 面向真实投递 | 简历评估、模拟笔试面试、作品集 |
| **P3 · 联网与主动** | 需联网与调度 | 公司情报、全流程模拟、主动跟进、看板 |

> 建议：P0 先立 Agent 骨架并平移 P1 工具，快速跑通"定位→项目→课程"最小闭环；再补求职闭环与主动层。

### 1.6 边界与取舍

| 取舍 | 原因 |
|------|------|
| 不做通用助手 | 定位专注职业成长，不抢通用 AI 的活 |
| 不编造公司数据 | 继承 skill 的数据纪律，查不到留空 |
| 记忆以用户档案为权威 | 不凭猜测，自评优先于推断 |
| 主动跟进默认关闭 | 尊重用户，不打扰；可开启 |
| 敏感信息不入公网 | 档案本地自持，可导出带走 |

## 二、架构：怎么搭

### 2.1 定位

把 skill 层从"宿主助手读取的指令文件"升级为"可自主运转的职业成长 Agent"：

- **内核（Agent 运行时）**：意图理解 → 规划编排 → 工具调用 → 反思调整 → 主动跟进
- **工具层**：九大职业能力封装为 tools（skill 的直接沉淀）
- **记忆层**：短期对话记忆 + 长期职业档案 + 向量索引 RAG
- **横切**：可视化看板、数据自持与导出

### 2.2 总体架构图

```
┌─────────────────────────────────────────────────────────────────┐
│  交互入口层（多端，同一套内核）                                     │
│  💬 对话（嵌入宿主助手）     🌐 Web 看板      ⌨️ CLI / API          │
└────────────────────────────┬────────────────────────────────────┘
                             │ 自然语言 / 意图
┌────────────────────────────▼────────────────────────────────────┐
│  Agent 运行时层（内核 · 必备）                                    │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌────────┐ │
│  │意图理解  │→ │规划与编排│→ │工具调用  │→ │反思与调整│→ │主动跟进 │ │
│  └─────────┘  └─────────┘  └────┬────┘  └─────────┘  └────────┘ │
│     解析目标/情绪/时间   多阶段工作流  调工具   回写档案/校准   跨会话续接 │
└────────────────────────────┬────────────────────────────────────┘
                             │ 调用（统一 schema）
┌────────────────────────────▼────────────────────────────────────┐
│  工具层（九大职业能力 = 可插拔 tools）                             │
│  目标定位雷达 · 技能差距 · 项目生成 · 课程生成 · 作品集 · 简历评估    │

                             │ 读写
┌────────────────────────────▼────────────────────────────────────┐
│  记忆与数据层                                                     │
│  ├ 短期对话记忆（会话上下文）                                     │
│  ├ 长期职业档案 career-profile（画像/目标/项目/难度偏好）          │
│  ├ 向量索引 RAG（简历/课程/复盘可检索）                            │
│  └ 学习进度（课程验收勾选 / 里程碑）                               │
└─────────────────────────────────────────────────────────────────┘
  横切：📊 可视化看板 · 🔒 数据自持与导出 · 📦 Markdown/JSON 迁移
```

### 2.3 分层说明

#### 2.3.1 Agent 运行时层（内核）

| 组件 | 职责 |
|------|------|
| 意图理解 | 从自然语言解析目标岗位、经验水平、时间预算、情绪信号 |
| 规划与编排 | 多阶段工作流（定位→差距→项目→课程→求职），可跳过/重入 |
| 工具调用 | 按 tools 注册表调用九大模块，统一输入输出 schema |
| 反思与调整 | 每阶段回写档案，按用户反馈平移难度、重排路径 |
| 主动跟进 | 跨会话续接、到里程碑提醒、阶段复盘（用户可关） |

#### 2.3.2 工具层

每个职业模块 = 一个 tool，含 `name / description / input_schema / output_schema`。规则：

- 全部继承 skill 的方法论口径（`references/methodology.md`）
- 结果区分"基于通用经验推断"与"可查证事实"
- 敏感数据（如真实简历细节）仅本地处理

#### 2.3.3 记忆与数据层

- 长期档案：`career-profile.md`（画像、目标岗位、能力矩阵、项目、难度偏好）——用户档案是权威来源
- 向量索引：对简历、课程、复盘做 embedding，支持 RAG 检索
- 进度：课程验收勾选、里程碑，供主动跟进读取

### 2.4 一次典型数据流

```
用户："我想从电气转去做后端，每周 10 小时，帮我排一年"
  ↓ 意图理解：目标=后端开发 · 起点=电气 · 预算=10h/周 · 周期=1年
  ↓ 规划编排：定位 → 差距 → 项目 → 课程
  ↓ 工具调用：目标定位雷达（出六维画像）→ 差距分析（排序缺口）→ 项目生成（2-3 个）→ 课程生成（拆课）
  ↓ 反思：按时间预算校准难度，写入 career-profile
  ↓ 返回：路线 + 第一个项目 + 第一课；标记"下次从这里继续"
  ↓（主动跟进开启后）下周自动复盘第一课完成情况，提示推进
```

### 2.5 从 skill 到 agent 的演进

```
skill 层（现在，SKILL.md 指令文件）
   │  九大模块 = 工具化的候选
   │  方法论   = 决策规则
   │  profile  = 记忆原型
   ▼
CareerOS Agent（本项目，目标）
   │  工具层：skill 九模块 → tools（几乎零改动平移）
   │  内核层：新增运行时（编排/反思/跟进/记忆）
   ▼
可独立运转的职业成长 Agent
```

> 关键洞察：skill 阶段沉淀的**模块边界 + 方法论纪律**，恰好是 agent 工具化的天然骨架——这正是"skill 后续发展为 agent"最顺的一条路。

### 2.6 技术栈选型

| 层 | 候选 | 倾向 |
|----|------|------|
| Agent 运行时 | LangGraph / 自研轻量状态机 / 直接复用宿主助手 | 先自研轻量（保持简单、可审计） |
| LLM 接入 | 现有大模型 API | 与宿主一致 |
| 向量索引 | 本地向量库 / 简单关键词检索起步 | 先关键词后向量 |
| 档案存储 | Markdown / JSON | Markdown（延续 skill，用户可带走） |
| 可视化 | ECharts / HTML 面板 | 后续做 Web 看板 |

> 以上为建议，属规划方向，非既定技术栈；待评审后定稿。

### 3.2 两个必须先看清的前提

1. **本项目目前只处在"规划阶段"**（`README.md` 原话：「规划阶段，目前只有文档」）→ **现在的 Python 门槛比将来低**。

### 3.3 学到什么程度才算够（验收标准）

| # | 能力 | 怎么验 |

| 6 | （阶段五才需要）能做可视化看板的数据接口 | 用 pandas 汇总出图表数据 |
